下面这套目录是按“初级架构师读代码”的学习路径来组织的：先建立全局心智模型 → 再逐层下钻到模块实现 → 最后总结可复用的架构/模式与演进方向。第一版以阅读为主，所以每一章都建议配“读代码路线图（从哪些文件/类/函数开始看）+ 关键设计点 + 常见坑”。

## 0. 前言与学习方式

* 你将学到什么：从脚本到工程化爬虫的架构拆解、稳定性、幂等、可观测性、可演进性
* 如何读这套代码：先跑起来、再看数据流、再看边界条件（重试/限速/失败）
* 环境与运行示例（直接引用你文档里的命令）

---

## 1. 系统全景：这是一个什么“抓取系统”

**目标**：读者能说清楚“它解决什么问题、输出什么数据、如何保证稳定与可追溯”。

内容建议：

* 需求拆解：列表→详情→附件→存储→回溯
* 端到端数据流（从 list_task 到 detail_task 到 sqlite/file）
* 状态机：`PENDING_DETAIL / DONE / FAILED` 的流转与约束（不回退）
* “为什么要落盘 Raw HTML + SHA256”：可审计、可回放、可二次解析

## 2. 架构分层与职责边界（你这套分层就是教材主线）

围绕你提到的：Scheduler / Fetcher / Parser / Pipeline / Storage / Monitor
逐层讲清：

* 每一层的“职责、输入输出、错误处理策略”
* 为什么要解耦“列表任务”和“详情任务”（独立调度、失败隔离、吞吐控制）

## 3. 配置与运行时行为：系统的“控制面”

**读代码入口**：`crawler/config.py`、`crawler/main.py`

* 重试/退避、限速、质量阈值 `MIN_CONTENT_LENGTH`

* 环境变量与 Cookie 注入（例如 `CRAWLER_TFSTK`）

## 4. Fetcher：可靠网络请求层怎么写

**读代码入口**：`fetcher.py`
重点讲“工程化爬虫的稳定性基座”：

* Session 复用、超时、异常分类
* 指数退避 + 抖动（为什么需要抖动）
* 403/429 的“礼貌策略”（降速、等待、避免雪崩）
* 可扩展点：代理、UA 池、熔断、统一错误码/异常类型

> 这一章是“架构师视角的非功能性需求落地”：稳定性与对方站点友好。

---

## 5. Parser（列表）：接口 JSON 解析与主键策略

**读代码入口**：`parser/list_parser.py`、`tasks/list_task.py`

* 列表抓取的输入输出：keyword/page-size/max-pages
* 唯一键策略：优先 `id`，退化 `index/url`（利弊、碰撞风险、改进方案）
* 写入 `policy_list` 的幂等 UPSERT 语义
* 新增记录默认 `PENDING_DETAIL` 的原因（异步化的任务编排）

---

## 6. Storage（SQLite）：幂等、增量与状态机落地

**读代码入口**：`storage/sqlite_store.py`

* 表结构为什么这么设计（list/detail 分表、元数据可追溯）
* UPSERT 与“DONE/FAILED 不回退”的业务约束如何实现
* “任务提取”：如何批量取 `PENDING_DETAIL`（分页、limit、并发安全的考虑）
* retry 计数与失败策略：max-retry 后如何处置（保留/人工干预/二次策略）

---

## 7. Detail Task：消费者模型与处理流水线

**读代码入口**：`tasks/detail_task.py`、`pipeline.py`
这是系统最核心的一条链：

* 从 DB 取任务 → fetch → raw_html 落盘 → parse → 下载附件 → 写 detail → 更新状态
* 为什么要“预留 pipeline”：为后续清洗、合并、去噪、结构化抽取做扩展点
* 失败回滚与幂等：重复跑 detail_task 为什么不会把数据搞乱

---

## 8. Parser（详情）：从 HTML 到正文与附件

**读代码入口**：`parser/detail_parser.py`、`storage/file_store.py`

* 候选容器 + 最长文本：这是一个经验型策略，为什么有效、什么时候失效
* 质量阈值 `MIN_CONTENT_LENGTH`：把“坏解析”转成“可重试失败”
* 附件识别策略：链接提取、命名规则（标题提示 + url hash）
* `parser_version` 的意义：解析逻辑演进时如何兼容历史数据

---

## 9. 文件落盘与可追溯性：Raw HTML / SHA256 / 附件

**读代码入口**：`storage/file_store.py`

* 按 `YYYY/MM` 分层存 Raw HTML：为什么要这样组织（规模、检索、归档）
* SHA256：如何验证内容是否变化、是否重复、是否被篡改
* 附件下载的幂等策略（文件名/哈希、防重复下载）

---

## 10. Monitor 与可观测性：从日志到指标

**读代码入口**：`monitor.py`

* 目前的“简易计数器”能回答哪些问题：成功率、失败原因分布、吞吐
* 生产级要补什么：结构化日志、trace id、指标（Prometheus）、告警（失败率/429）
* 读者应该形成的意识：可观测性是架构能力的一部分

---

## 11. 设计模式与架构原则总结（把读过的代码抽象成套路）

把代码里的“隐形模式”显性化：

* **分层架构**：Fetcher/Parser/Storage/Pipeline 的边界
* **管道（Pipeline）/ETL 思维**
* **命令模式**：`main list/detail` 作为命令入口
* **策略模式**：限速策略、解析策略、主键策略（现在是硬编码，如何抽成可插拔）
* **仓储模式（Repository）**：sqlite_store 对 DB 细节封装
* **幂等设计**：UPSERT + 状态机 + Raw 数据留存
* **失败即数据**：retry 计数、FAILED 保留用于运营/人工处理
